# U2.2 — Organizar el equipo para iniciar el proyecto

## 📌 Actividades

### 1. Reconocer cómo puede participar cada integrante

Cada integrante deberá reflexionar sobre su participación inicial en el proyecto.

No se trata de identificar quién es "experto" en algo, sino de reconocer:

- qué actividades le interesan;
- en qué considera que puede colaborar inicialmente;
- qué experiencias escolares o personales podrían ser útiles;
- qué le gustaría aprender o desarrollar durante el proyecto.

Pueden utilizar una tabla como la siguiente:

| Integrante | Me interesa participar en... | Inicialmente puedo colaborar en... | Me gustaría aprender o desarrollar... |
|---|---|---|---|
| Jaqueline |---|---|---|
| Oscar |---|---|---|
| Jesus |---|---|---|
| Lazaro |---|---|---|
| Angel |---|---|---|

Algunas respuestas pueden estar relacionadas con investigar información,
documentar, organizar actividades, comunicarse con otras personas, programar,
hacer cálculos, elaborar diagramas, realizar pruebas, construir, diseñar,
analizar información o aprender a utilizar alguna herramienta.

**No es necesario que el integrante ya domine aquello en lo que desea
participar.**

---

### 2. Identificar necesidades de aprendizaje y apoyo del equipo

A partir del punto de partida establecido en U2.1, analicen qué cosas necesitará
el equipo aprender, investigar, consultar o conseguir para poder avanzar.

Pueden apoyarse en la siguiente tabla:

| Necesidad identificada | ¿Qué sabemos actualmente? | ¿Qué necesitamos hacer para atenderla? |
|---|---|---|
|Invetigar sobre potencia instalada en un sistema| | |
|Investigar sobre equipo de seguridad en una intalacion fotovoltaica| | |
|Investigar sobre el tipo de terreno en las zonas rurales en Queretaro| | |
|Investigar sobre los elementos que componen todo un sistema fotovoltaico| | |
|(Añadir cualquier otro si es el caso)| | |

Por ejemplo, una necesidad podría requerir:

- investigar un tema;
- aprender a utilizar una herramienta;
- consultar a una persona con mayor experiencia;
- solicitar información a una organización o comunidad;
- buscar documentación técnica;
- conocer alguna norma;
- realizar posteriormente observaciones, pruebas o mediciones.

> En este momento **no tienen que resolver estas necesidades**. El objetivo es
> reconocerlas para poder considerarlas durante la planeación posterior del
> proyecto.

### 3. Distribuir responsabilidades iniciales de organización (Este apartado lo llenaremos despues de completar los primeros dos puntos)

El equipo deberá acordar quién dará seguimiento inicialmente a algunas
responsabilidades necesarias para organizar el trabajo.


| Responsabilidad | Integrante(s) | ¿Qué deberá cuidar o verificar? |
|---|---|---|
| Coordinación | | |
| Documentación | | |
| Seguimiento en GitHub | | |

Estas responsabilidades:

- pueden ser compartidas;
- pueden rotarse;
- no otorgan mayor autoridad a un integrante;
- no sustituyen la participación del resto del equipo.

> **Todos siguen siendo responsables del proyecto.**

---

### 4. Establecer acuerdos de trabajo (Contestar las preguntas poniendo (Nombre):-Propuesta- )

El equipo deberá discutir y establecer acuerdos básicos que utilizará durante
el desarrollo del proyecto.

Como mínimo acuerden:

- ¿Cómo se comunicarán?
- ¿Cómo organizarán y distribuirán las actividades?
- ¿Cómo acordarán fechas y darán seguimiento a pendientes?
- ¿Qué harán cuando un integrante tenga dificultades para cumplir una actividad?
- ¿Cómo resolverán diferencias o desacuerdos?
- ¿Cómo revisarán un trabajo antes de considerarlo terminado?
- ¿Cómo asegurarán que todos conozcan las decisiones tomadas?

Los acuerdos deberán ser **realistas y aplicables**.
